## 一、已确认的 checksum 语义

当前 WSL 协议中：

```text
multipart 表单字段 checksum
=
task.json.checksum
=
任务文件集合摘要
```

不是 ZIP 文件本身的 SHA-256。

任务摘要计算规则为：

```text
SHA256(
    relative_path + "\0"
    + size_bytes + "\0"
    + file_sha256 + "\n"
)
```

其中 `task.json.files[]` 必须先按 `relative_path` 排序。

因此当前上传代码：

```python
data={"checksum": package.checksum}
```

语义正确，不要改成 ZIP 文件 SHA-256。

WSL 会检查：

```text
multipart checksum == task.json.checksum
```

不一致会返回 HTTP 400：

```text
multipart checksum does not match task.json
```

请更新现有测试和代码注释，消除“multipart checksum 是 ZIP SHA-256”的错误假设。

## 二、ZIP 文件集合规则

ZIP 实际文件集合必须严格等于：

```text
{"task.json"} ∪ {task.json.files[].relative_path}
```

规则：

1. `task.json` 本身不放入 `files[]`。
2. `images/0.jpg`～`images/7.jpg` 必须在 `files[]` 中声明。
3. `metadata.json`、`quality.csv`、`cameras.json` 等额外文件可以上传。
4. 每个额外文件都必须在 `files[]` 中声明。
5. 未声明文件会导致 HTTP 400。
6. 声明但 ZIP 中缺失的文件会导致 HTTP 400。
7. 每个文件的 `size_bytes` 和 SHA-256 必须与实际文件一致。

第一次跨机器联调建议只包含：

```text
task.json
metadata.json
images/0.jpg
images/1.jpg
images/2.jpg
images/3.jpg
images/4.jpg
images/5.jpg
images/6.jpg
images/7.jpg
```


## 七、实现 HTTP Range 分块下载

逐块请求：

```http
GET /result/<task_id>
Range: bytes=<start>-<end>
If-Range: "<完整文件SHA-256>"
```

每块验证：

```text
HTTP 状态码 == 206
Content-Range 与请求范围一致
Content-Length 正确
X-GO-Magic == GOBJ
X-GO-Protocol-Version == 1.0
X-GO-Message-Type == ply_result
X-GO-Task-ID 匹配
X-GO-Capture-ID 匹配
X-GO-File-Size 与 metadata 一致
X-GO-SHA256 与 metadata 一致
X-GO-Chunk-Index 正确
X-GO-Chunk-Count 正确
X-GO-Chunk-SHA256 校验通过
```

结果保存到：

```text
<result_root>/<capture_id>/<task_id>/3DGS.ply.part
```

全部接收完成后：

1. `flush()`。
2. `os.fsync()`。
3. 检查最终文件长度。
4. 流式计算整文件 SHA-256。
5. 与 metadata 的 SHA-256 比较。
6. 全部通过后使用原子重命名生成：

```text
<result_root>/<capture_id>/<task_id>/3DGS.ply
```

失败时不得生成正式 `.ply`。

不得一次性把整个 PLY 读取到内存。
